# 길냥이 식당

작은 밤, 따뜻한 한 끼. Phaser 3 + TypeScript + Vite로 만든 세로형 픽셀 힐링 경영 게임입니다. 현재 버전은 **0.3.5 · 골목 친구들의 다섯 얼굴**입니다.

## 실행

Node.js 20.19+ 또는 22.12+에서:

```bash
npm ci
npm run dev
```

터미널에 표시되는 주소를 브라우저로 엽니다. 개발 서버의 Network 주소로 같은 Wi-Fi의 모바일에서도 접속할 수 있습니다.

```bash
npm run build
npm run preview
```

`dist/`가 정적 호스팅 배포 결과물입니다. GitHub Pages용 저장소 경로(`/gilnyang/`)는 `vite.config.ts`에서 설정했습니다. `main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 빌드 후 Pages에 배포합니다. 처음 한 번 저장소의 **Settings → Pages → Source → GitHub Actions**를 선택하세요. 배포 주소는 `https://wanttogames.github.io/gilnyang/`입니다. 서버·DB·외부 API 없이 실행되며 입력과 진행 데이터는 서버로 전송하지 않습니다. 개발 서버의 핫 리로드 통신은 개발 환경에서만 사용됩니다.

단일 HTML 파일을 다시 만들려면 `npm run build` 후 `python scripts/export_standalone.py`를 실행하세요. 생성되는 `release/gilnyang-play.html`은 그래픽·글꼴·게임 코드가 들어 있는 단일 실행 파일입니다. 내려받아 Chrome/Edge 등으로 열면 플레이할 수 있습니다. 저장은 파일/사이트 주소와 브라우저별로 분리되므로 지속적인 플레이에는 같은 주소를 사용하세요. HTML 파일을 옮기거나 이름을 바꾸면 저장이 달라질 수 있습니다.

## 0.3.5 · 골목 친구들의 다섯 얼굴

- 콩이(`kong`): 고등어태비 고양이. 회갈색 바탕, 굵은 이마 M 패턴/몸 줄무늬/링 꼬리, 조금 다부진 체형입니다. 기존 성격·대사·기록을 유지합니다.
- 까망(`kkamang`): 차콜/거의 검정/푸른 회색 3단계, 가는 황금 눈, 높은 귀와 긴 몸, 몸 가까이에 둔 꼬리입니다. 기존 식사 tween에서 들뜬 점프를 줄이고 반짝임은 1개만 사용합니다.
- 몽실(`mongsil`): 밝은 황갈색/크림 털, 계단형 볼털과 가슴털, 작은 얼굴/귀, 등 뒤 풍성한 말린 꼬리의 포메라니안입니다.
- 기존 CharacterArt에 세 디자인만 추가했습니다. 48×48 및 normal/blink key, 공통 Image/idle/식사/입장·퇴장 구조를 유지합니다. 새로운 행동/꼬리 애니메이션 시스템은 없습니다.
- 다섯 주요 손님의 도감 이미지를 본체와 같은 픽셀 데이터로 생성합니다. 나비·두부 외형은 픽셀 단위로 동일합니다.
- SaveData/캐릭터 ID/친밀도·골드/스토리/요리/레시피/날씨 로직 변경 없음.

## 0.3.1 · 살랑살랑 나비

나비만 기존 도트 색/외형을 유지한 몸·귀·꼬리 레이어로 렌더링합니다. 다른 캐릭터는 기존 Image/눈 깜빡임/idle 그대로입니다. 저장/스토리/요리/보상 데이터는 변경하지 않습니다.

- 몸의 아주 작은 호흡, 느린 꼬리, 2.5~5초 랜덤 눈 깜빡임, 4~8초 랜덤 귀 움직임.
- 초반 꼬리는 작게, 친밀도 10 이상 또는 스토리 2단계 이후 조금 더 편안하게, 완료 후 더 부드럽고 넓게 움직입니다.
- NORMAL: 작은 고개 움직임. GOOD/취향 맞춤: 조금 빠른 꼬리와 반짝임 2개. PERFECT: 빠른 꼬리, 약 2px 들림, 잠깐 감은 눈, 반짝임 3개.
- 실제 친밀도 증가 시 도트 하트 1~2개, 약 1초 후 제거. 반응은 1~2초 이내 기본 상태로 돌아옵니다.
- 기존 스토리 감정 shy/quiet/smile을 재사용합니다. 조심스러움에는 귀 쫑긋과 작은 들림, quiet에는 거의 멈춘 꼬리/낮춘 귀/느린 몸, smile에는 감은 눈과 반짝임 1개.
- 스토리 감정 > 음식 반응 > 친밀도 반응 > idle. quiet에는 하트/반짝임을 억제하며 식사 반응이 끼어들지 않습니다.
- NabiView가 소유한 Tween/TimerEvent/effect만 관리합니다. 같은 부위의 tween은 교체하고, 퇴장 시작/destroy/Scene shutdown에서 전부 정리합니다.
- 기본 반복 tween 2개, 랜덤 예약 timer 2개, 동시 이펙트 최대 5개. 새 update loop나 particle emitter 없음.

구현 파일: `src/game/NabiView.ts`, `src/scenes/BootScene.ts`, `src/scenes/RestaurantScene.ts`. 버전/문서만 함께 갱신했습니다. 기존 UI/스토리 내용/SaveData/요리 파일은 그대로입니다.

## 0.3.0 · 오늘도 김 많이

나비 한 명의 첫 드라마 아크를 추가합니다. 기존 캐릭터 외형, 음식, 주문/요리/보상, 날씨와 다른 손님 이야기는 유지합니다. 김 취향 → 익숙한 냄새 → 옛 주먹밥 → 할머니를 기다림 → 여기 오고 싶은 마음으로 천천히 이어집니다. 할머니가 보이지 않는 이유는 공개하지 않습니다.

| 이벤트 | 방문(이번 방문 포함) | 친밀도(입장 시) | 앞 이벤트 이후 방문 | 위치 |
|---|---:|---:|---:|---|
| 1 처음 만난 손님 | 1 | 0 | — | 주문 전 |
| 2 김을 많이 | 3 | 3 | 2회 | 주문 전 |
| 3 익숙한 냄새 | 5 | 8 | 2회 | 주문 전 |
| 4 그 사람이 만들어주던 것 | 7 | 12 | 2회 | 식사 후 |
| 5 기다림 | 10 | 18 | 3회 | 식사 후 |
| 6 오늘도 김 많이 | 13 | 24 | 3회 | 주문 전 + 식사 후 |

모든 조건과 앞 이벤트 완료가 필요합니다. 이전 이벤트와 다른 밤이어야 합니다. 높은 친밀도의 기존 저장에서도 첫 인사부터 시작하며, 마지막 이벤트 앞/뒤 대화는 하나의 주요 이벤트입니다. 한 방문에 한 이벤트, 한 밤에 최대 한 이벤트입니다. 비/눈/맑음 모두 진행 가능하며 날씨를 강제하지 않습니다.

대화는 큰 버튼으로 넘깁니다. 중요한 문장 앞에 0.3~0.5초 정적이 있고, 탭하면 바로 표시합니다. 화자를 구분하고 기존 픽셀 캐릭터의 고개/눈/작은 크기 변화로 감정을 표현합니다. 완료 후 도감에 여섯 기억과 작은 완료 표시가 남습니다. 완료 이후에도 나비는 일반 방문합니다.

`customers[id].characterStory`에 `stage`, `lastEventVisit`, `lastEventNight`와 진행 중 `pending(eventId, visit, night, part, line)`을 저장합니다. 기존 `storyStage`는 원래 짧은 이야기 상태로 보존합니다. LocalStorage 키와 저장 version 2 유지, version 1/2의 새 필드가 없으면 0단계 초기화. 기존 골드/친밀도/날씨/밤/레시피/가구는 유지합니다. 문장 넘김마다 자동 저장하며, 서빙 후 재접속은 지급을 반복하지 않고 남은 식사 후 대화부터 이어집니다.

### 확장과 검증

- `src/data/characterStories.ts`: 캐릭터 ID별 이벤트 데이터. 이번에는 나비만 등록합니다.
- `src/systems/CharacterStoryManager.ts`: 조건/예약/단계/복원. 데이터가 없는 손님은 기존 이야기 사용.
- `src/ui/StoryDialogue.ts`: 기존 패널의 화자/정적/넘기기. 별도 컷신 Scene 없음.
- `npm run test:story`: 저장 호환/문장 복원/진행 조건/중복 방지/다른 손님 회귀 검증.
- `npm run build`: TypeScript/Vite 빌드.
- 실제 브라우저 검증 범위는 `VERIFICATION.md`에 기록합니다.

## 0.2.2 · 어묵 개별 익힘 미니게임

기존 주먹밥 3단계는 유지합니다. 어묵의 마지막 `한 번 건져내기`를 `사각·삼각·둥근 꼬치 3개를 각각 건지기`로 바꿉니다. 재료·국물 추가 선택, 주문·완성·서빙·보상·저장 흐름은 그대로입니다.

- 꼬치마다 익는 속도가 조금 다릅니다(전체 익힘 6.5/7/7.5초).
- **파랑 설익음 → 노랑 적당함 → 주황 PERFECT → 빨강 퍼짐**. 각 카드에 상태 이름과 진행 게이지를 표시합니다.
- 어묵 그림뿐 아니라 카드 전체가 터치 영역입니다. PC 클릭, 터치, 버튼의 기본 키보드 입력을 지원합니다.
- 주황 구간은 약 1.3~1.5초입니다. 냄비 업그레이드는 기존과 마찬가지로 PERFECT 범위를 넓힙니다.
- 모두 건진 뒤 개별 점수와 평균 결과를 확인하고 기존 서빙 화면으로 복귀합니다.
- 두 음식 공통으로 `0~59 NORMAL / 60~89 GOOD / 90~100 PERFECT`. 기존 +10/+12/+15 골드와 +1/+2/+3 친밀도를 사용하며 취향·방석 보너스도 유지합니다.
- 너무 빨리 또는 늦게 건져도 NORMAL로 완성됩니다. 조리 중 새로고침하면 해당 주문부터 다시 시작하고, 서빙 후에는 보상을 중복 지급하지 않습니다.
- 조리 시간은 재료·국물 선택을 포함해 약 6~12초를 목표로 하며, 결과를 읽는 시간과 입력 속도에 따라 달라집니다.

## 0.2.1 · 참치 주먹밥만 개선

기존 재료 선택과 취향 추가 선택은 유지하며, 주먹밥의 마지막 `2초 꾹 누르기`를 아래 세 단계로 바꿉니다. 다른 음식·손님·대사·날씨·해금·저장 형식·보상은 그대로입니다.

1. **밥 양**: 왕복 게이지가 가운데에 왔을 때 `이만큼 담기`. 놓치면 다음 왕복을 기다릴 수 있습니다.
2. **모양 만들기**: 왼쪽 → 오른쪽 → 왼쪽 → 오른쪽. 다음 입력까지 0.8초의 짧은 간격이 있으며 더 천천히 눌러도 감점하지 않습니다. 잘못 누르면 안내하고 다시 선택할 수 있습니다. 네 번의 손길에 따라 주먹밥 모양이 삼각형으로 변합니다.
3. **김 감기**: 김이 가운데에 왔을 때 `지금 김 감기`. 김이 음식에 감기는 모습을 보여줍니다.

세 점수의 평균을 반올림해 0~100점을 계산합니다. `0~59 NORMAL`, `60~89 GOOD`, `90~100 PERFECT`를 기존 품질 `보통/맛있음/완벽`으로 연결합니다. 골드/친밀도는 기존 +10/+1, +12/+2, +15/+3을 유지합니다. 기존 취향 +2와 방석 +1도 유지합니다. 낮은 점수에서도 음식을 완성해 손님에게 제공할 수 있습니다.

조리는 재료/취향 선택과 단계 전환을 포함해 약 8~15초의 느긋한 플레이를 목표로 합니다. 제한 시간은 없습니다. 조리 중에는 하단 메뉴를 숨기고, 종료 후 기존 서빙 화면으로 복귀합니다. 클릭/터치 모두 같은 버튼을 사용하며, 모양 만들기는 포커스가 조리 화면 안에 있을 때 좌우 방향키도 사용할 수 있습니다.

스토리 시스템, 콤보, 세부 취향, 추가 음식 미니게임은 이번 변경에 포함하지 않습니다. 저장 키와 v1/v2 호환은 그대로입니다. 요리 도중 새로고침하면 해당 손님의 주문부터 재시작하고, 서빙 후에는 보상을 중복 지급하지 않고 다음 손님으로 이어집니다.

## 저장 방식

키: `alley-cat-diner-v1`을 그대로 유지합니다. 저장 형식은 v2이며 기존 v1 데이터를 읽어 자동 변환합니다. 골드·밤·식당 레벨·손님 방문/친밀도/이야기/취향·레시피·꾸미기·사운드 설정·진행 중인 밤 정산·현재 날씨·아직 확인하지 않은 레시피 해금 안내를 저장합니다. 브라우저 데이터 삭제 시 초기화됩니다. 식당 레벨은 누적 서빙 10회마다 1씩 오릅니다.

손님을 서빙한 시점에 보상과 방문 수를 함께 저장합니다. 요리 도중 새로고침하면 해당 손님의 주문부터 다시 시작합니다. 서빙 후 새로고침하면 다음 손님부터 이어집니다. 마지막 손님까지 서빙했으면 정산 화면을 복원합니다. 해금된 대화는 도감에서 다시 볼 수 있습니다.

## 구조와 에셋 교체

- `src/data/`: 손님·음식·재료·대화·꾸미기 데이터
- `src/systems/`: 저장·요리 판정·진행·친밀도·오디오
- `src/scenes/RestaurantScene.ts`: Phaser 식당 장면과 밤 상태 전이
- `src/scenes/CookingScene.ts`: 조리 UI와 마우스/터치 입력
- `src/scenes/CustomerBookScene.ts`, `ResultScene.ts`: 도감·정산 화면
- `src/ui/UI.ts`: 공통 UI 렌더링
- `src/scenes/BootScene.ts`: 48×48 절차적 캐릭터 텍스처 생성

조리/도감/정산은 별도 Phaser 렌더 장면을 띄우기보다 HTML UI 컨트롤러로 구현했습니다. 식당 장면을 계속 보여주면서 읽기 쉬운 글자와 터치 버튼을 제공합니다. 게임 로직은 데이터와 시스템 모듈로 분리되어 있습니다.

캐릭터를 PNG 에셋으로 교체하려면 BootScene의 절차적 생성 부분을 `this.load.image(id, ...)`로 바꾸고 동일한 텍스처 키(`chef`, `nabi`, `nabi-blink` 등)를 유지하세요. 요리와 도감의 CSS 아이콘은 `UI.food()` / `CustomerBookScene`에서 이미지로 교체할 수 있습니다. 배경은 `RestaurantScene.drawStreet()`에서 교체합니다. 외부 에셋 다운로드는 실행 시 필요하지 않습니다.
